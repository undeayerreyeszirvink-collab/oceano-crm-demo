# 一句话结论

要让 Gemini 不扩展，本质是三件事：**锁死输出边界 + 明确禁止行为 + 给失败判定标准**。

---

# 1）最强约束模板（推荐直接用）

这是实战最稳的写法（适合你要“完全不扩展”的场景）：

```
任务：对输入文本进行处理

硬性约束（必须全部满足）：
1. 不得添加任何新信息
2. 不得进行解释、举例、延伸、总结
3. 不得改变原意
4. 不得增加字数（允许减少或保持）
5. 输出必须严格基于原文

输出规则：
- 只输出处理后的文本
- 不要包含任何说明、前后缀、解释

违规判定（任一即失败）：
- 出现原文没有的信息
- 出现解释性语句
- 内容长度明显增加

输入：
{{你的原文}}
```

👉 关键点：

- “违规判定”这一段非常重要（很多人漏掉）
    
- Gemini 对“规则 + 判定”组合更敏感
    

---

# 2）如果你要“完全不改”（极限模式）

```
请逐字输出以下内容：
- 不允许修改任何一个字
- 不允许添加或删除任何字符
- 不允许格式变化

如果无法做到，请只输出：ERROR

内容：
{{原文}}
```

👉 这个适合：

- 法律文本
    
- 合同
    
- prompt拼接
    

---

# 3）如果你只想“压缩但不扩展”

```
请在不增加任何新信息的前提下压缩以下内容：

约束：
- 只能删除冗余，不可新增信息
- 不可改变原意
- 不可进行解释或推导
- 优先删除形容词、副词、重复表达

输出：
只输出结果文本

输入：
{{原文}}
```

---

# 4）如果你发现它还是“忍不住扩展”

加这一句（很有效）：

```
你倾向于过度补充内容。本任务中这是错误行为，请严格避免。
```

👉 这是利用模型的“自我修正倾向”，实测对 Gemini 特别有效。

---

# 5）再提升一层（结构锁死）

如果你是结构化内容（比如表格/字段），用这个：

```
仅允许在以下结构内输出，不得新增字段：

字段：
- 标题：
- 内容：

规则：
- 每个字段内容必须来自原文
- 不得新增字段
- 不得增加信息

输入：
{{原文}}
```

---

# 常见错误（你可能正在踩）

1）❌ 写“请不要扩展”  
→ 太模糊，模型会忽略

2）❌ 没有“输出格式约束”  
→ 它会自动补解释

3）❌ 没有“失败标准”  
→ 模型不知道什么叫违规

4）❌ 同时要求“优化 + 不扩展”  
→ 这是冲突指令（必须二选一）

---

# 如果你要更狠一点（工程级）

在 API 里配合：

- temperature = 0
    
- top_p = 0.1
    
- max_output_tokens = 接近原文长度
    

👉 这比 prompt 还关键

# 给你一个更贴近你场景的优化版（你之前做表格/合同很适合）

```
任务：整理文本（非创作）

绝对禁止：
- 新增信息
- 推理
- 解释
- 改写含义

允许：
- 仅做排版优化
- 仅做结构重组

校验：
如果输出内容的信息量 > 输入，则判定为错误

输出：
仅输出最终结果
```
