# 潮玩快闪店销量预测系统 — LLM原生仿真设计

## 核心思路

不做参数化规则引擎，不做统计回归，不分四步慢慢加AI。

**直接用大模型驱动消费者Agent进行行为仿真**——每个Agent是一个带有人设prompt的LLM调用，它会像真人一样"逛"这个快闪店，做出进店、浏览、犹豫、购买、放弃、打卡的决策。从大量Agent的群体行为中涌现出销量预测。

这就是MiroFish的方法论核心：不是算出来的预测，是"演"出来的预测。

---

## 系统总览

```
输入                        仿真引擎                          输出
                    ┌─────────────────────┐
 场地数据 ─────────▶│                     │
                    │   LLM 驱动的        │──────▶ 预测报告
 IP/SKU数据 ───────▶│   多Agent仿真循环    │──────▶ SKU级备货方案
                    │                     │──────▶ 14天销售曲线
 时段/天气/竞品 ───▶│                     │──────▶ 风险预警
                    └─────────────────────┘──────▶ 运营节奏建议
                           ▲
                           │
                    每场快闪的真实数据回流校准
```

整个系统只有**一个核心循环**：构建世界 → Agent仿真 → 提取结果。没有中间态，不需要先跑规则引擎再升级。

## 第一层：世界构建

每次预测任务启动时，系统先构建一个"快闪店世界"——这是所有Agent行动的舞台。

### 世界描述文档（World Prompt）

这是一份结构化的场景描述，喂给每个Agent作为环境上下文。由系统根据输入数据自动生成。

```markdown
## 世界设定：静安大悦城B1中庭 × Chiikawa快闪店

### 场地
- 上海静安大悦城B1层中庭，约60㎡
- 工作日日均经过客流约8000人，周末约15000人
- 客群画像：18-30岁占58%，女性占67%，消费力中高
- 周边业态：奶茶店、潮牌集合店、电影院

### 快闪店
- IP：Chiikawa（吉伊卡哇），日本治愈系IP
- 周期：2026年4月1日-4月14日（含清明假期）
- 视觉：粉白主色调，3米高Chiikawa主题装置，打卡墙

### 在售商品
| SKU | 品类 | 定价 | 初始库存 | 特性 |
|-----|------|------|----------|------|
| Chiikawa限定盲盒 | 盲盒 | ¥69 | 600 | 限定款，有隐藏 |
| 兔兔毛绒公仔30cm | 毛绒 | ¥168 | 200 | 主力款 |
| 乌萨奇挂件三件套 | 挂件 | ¥89 | 300 | 性价比款 |
| 仓鼠亚克力立牌 | 文创 | ¥39 | 500 | 引流款 |
| 联名限定帆布袋 | 文创 | ¥128 | 150 | 限量款 |
| 角色贴纸包（随机） | 文创 | ¥19 | 1000 | 凑单款 |

### 时段特征
- 4月1日（周二）：普通工作日
- 4月4-6日（周五-周日）：清明假期，预计客流翻倍
```

这份文档不需要人工写，系统根据场地方和IP方提交的结构化数据自动拼装。

## 第二层：Agent体系

### 消费者Agent

每个消费者Agent是**一次LLM调用**，带有特定的人设prompt和行为指令。

**Agent人设prompt示例（Z世代盲盒爱好者）：**

```
你是小雨，22岁，上海某大学大四学生。你是Chiikawa的忠实粉丝，
关注了所有相关的小红书账号，家里已经有十几个盲盒和三个毛绒公仔。
你今天和闺蜜约了去大悦城逛街，刚在小红书上看到Chiikawa快闪店
开了，非常兴奋。你这个月的零花钱还剩大约400块。
你的消费习惯：看到喜欢的会冲动购买，但超过200块的东西会犹豫；
喜欢抽盲盒的感觉；买到东西一定会拍照发小红书。
```

**Agent行为指令：**

```
现在你来到了大悦城B1，看到了Chiikawa快闪店。请根据你的人设，
逐步描述你的行为和决策：

1. 你会进店吗？为什么？
2. 进店后你会浏览什么？被什么吸引？
3. 你会购买哪些商品？每件的决策理由是什么？
4. 你的总消费金额是多少？
5. 你会在社交媒体上分享吗？如果会，你会怎么发？

请以JSON格式输出你的决策结果：
{
  "entered": true/false,
  "browsed": ["SKU名称", ...],
  "purchased": [{"sku": "名称", "quantity": N, "reason": "原因"}],
  "total_spent": 金额,
  "social_post": true/false,
  "social_platform": "小红书/抖音/无",
  "social_reach_estimate": 预估触达人数,
  "mood_after": "满足/一般/失望/后悔",
  "would_return": true/false
}
```

### Agent原型库

不需要为每个Agent手写人设。系统维护一个**原型模板库**，每次仿真时根据场地客群画像按比例实例化：

| 原型 | 生成人设时的关键变量 | 典型占比（视场景调整） |
|------|---------------------|----------------------|
| IP铁粉 | 拥有该IP周边数量、关注时长、收藏品清单 | 10-20% |
| 潮玩泛爱好者 | 喜欢多个IP、有盲盒习惯、预算中等 | 15-25% |
| 路过好奇型 | 不了解IP、被装置/排队吸引、预算低 | 30-40% |
| 社交驱动型 | 被朋友/KOL推荐来、打卡目的强、消费随机 | 10-20% |
| 亲子陪伴型 | 带孩子来、孩子选择为主、关注安全和体验 | 5-15% |
| 收藏家/黄牛 | 目标明确、大量购买限定款、不受价格影响 | 3-8% |

每个原型实例化时，LLM根据模板生成**具体化的人设**（随机名字、具体背景、具体偏好），确保同一原型的不同实例有行为差异，这正是LLM的优势——不需要手动设随机参数，模型自己就会产生自然的个体差异。

### 特殊Agent（非消费者）

除消费者外，仿真中还可以引入影响环境的Agent：

- **KOL Agent**：模拟某个小红书博主在第N天发布探店帖后带来的客流脉冲
- **天气Agent**：下雨天自动衰减当日客流、改变消费者心态（"下雨天不想逛"vs"下雨天商场里正好"）
- **竞品Agent**：模拟同城竞品快闪开业/促销对客流的分流效应

这些Agent不需要复杂建模，只需要在仿真循环中注入**事件**改变世界状态。

## 第三层：仿真循环

### 主循环（按天推进）

```
for 第D天 in Day1..Day14:

    ── 1. 更新世界状态 ──
    
    LLM调用：给定世界描述 + 当天日期/天气/事件，
    生成当天的"世界状态摘要"：
    - 今天是周几，预计经过客流N人
    - 天气情况及影响
    - 是否有特殊事件（KOL发帖、竞品开业）
    - 当前各SKU剩余库存
    - 昨天的社交传播是否带来了今天的额外客流
    
    ── 2. 批量Agent仿真 ──
    
    根据当日客流和原型比例，确定今天需要仿真的Agent数量。
    
    关键设计：不需要仿真每一个路过的人。
    从N人客流中按原型比例抽样M个Agent进行LLM仿真
    （比如每天仿真50-100个Agent），然后按比例放大。
    
    每个Agent收到的输入：
    - 世界描述文档（完整场景）
    - 当天世界状态摘要
    - 自己的人设prompt
    - 行为指令（要求JSON输出）
    
    每个Agent输出结构化决策JSON。
    
    ── 3. 汇总当日结果 ──
    
    聚合所有Agent的决策：
    - 当日进店率 = 进店Agent数 / 总仿真Agent数
    - 当日各SKU销量 = 各Agent购买的该SKU数量之和 × 放大系数
    - 当日GMV = 各SKU(销量 × 单价)之和
    - 当日社交传播量 = 发帖Agent数 × 平均触达 → 注入后续天数的增量客流
    - 当日缺货事件 = 哪些SKU库存归零
    
    ── 4. 更新库存和传播池 ──
    
    各SKU库存扣减当日销量。
    社交传播的"延迟转化"加入后续天数的客流预测。
    如果有SKU售罄，后续天数的Agent将看到"该商品已售罄"的信息。

输出：14天仿真日志，包含每天的GMV、SKU销量、客流、传播、库存变化。
```

### 多轮仿真（处理不确定性）

同一个场景运行**多轮仿真**（比如10-20轮），每轮的Agent实例化都是不同的（LLM自然产生个体差异），最终取多轮结果的分布：

- GMV中位数作为主预测
- P25-P75作为置信区间
- 多轮中一致出现的"爆款SKU"和"滞销SKU"可信度高
- 多轮结果分歧大的SKU标记为"不确定，建议小批量测试"

### 成本控制

LLM仿真的核心成本是API调用。估算：

```
每天仿真Agent数: 80个
快闪周期: 14天
单轮总调用: 80 × 14 = 1,120次
多轮仿真: 10轮
总调用次数: ~11,200次

每次调用约500 token输入 + 300 token输出
总token消耗: ~900万 token

通过OpenClaw路由到性价比合适的模型，
成本可控制在一次完整预测几十到一两百元级别。
相对于一场快闪50万GMV的决策价值，完全可接受。
```

进一步优化：
- 不需要每个Agent都用最强模型，路过好奇型用轻量模型，收藏家/铁粉用强模型
- 并行调用，一天80个Agent可以同时发起，总时间几分钟
- OpenClaw网关层做模型路由和成本优化

## 第四层：报告与交互

### 结构化报告（自动生成）

仿真完成后，将14天仿真日志喂给一个"报告Agent"（一次LLM调用），指令为：

```
你是一位资深快闪店运营顾问。以下是一次14天快闪店仿真的完整数据。
请生成一份可直接指导业务决策的预测报告，包含：

1. GMV预测总览（中位数 + 区间 + 置信度）
2. Top 10 SKU排名及各自的备货建议
3. 14天销售节奏（哪几天是峰值、何时需要补货）
4. 关键风险点（缺货、天气、竞品分流）
5. 3条最重要的运营建议

语气专业但直白，数字精确，建议可执行。
```

### 交互式追问

报告生成后，用户（IP方/场地方/运营方）可以直接追问：

- "如果我把盲盒定价从69降到59，会怎样？" → 重新跑一轮仿真，Agent看到新定价后的行为变化
- "如果把快闪缩短到7天呢？" → 仿真只跑7天
- "第5天如果加一个买二送一活动呢？" → 在Day5的世界状态中注入促销事件
- "为什么预测盲盒是爆款？" → 回溯仿真日志，展示哪些类型的Agent购买了盲盒以及他们的决策理由

这种交互能力是规则引擎和统计模型完全做不到的——因为每个Agent的决策都有自然语言的理由，可以直接追溯和解释。

## 数据飞轮

```
第一场快闪：
  预测 → 执行 → 收集真实数据 → 对比偏差
  │
  ▼
  哪些原型的行为描述需要调整？
  ├── 比如"Z世代铁粉"的实际客单价比仿真高20% → 调高预算参数
  ├── 比如"路过好奇型"的实际进店率比仿真低 → 调整进店prompt
  └── 比如"社交传播"效应比预期弱 → 调整传播转化描述

  调整方式：修改原型模板prompt中的描述文字和数值
  不需要重新训练模型，只需要优化prompt

第五场快闪：
  原型模板已经经过4轮校准
  预测准确率从±40%收敛到±20%

第十场快闪：
  积累了多个"场地×IP"组合的真实数据
  可以在Agent人设中注入"你上次在XX商场买过YY"的经验记忆
  预测准确率进一步提升
```

关键点：**校准不是调参数，是改prompt。** 这是LLM原生仿真和传统参数化模型的根本区别——优化手段是自然语言级别的，运营人员就能做，不需要算法工程师。

```

内部路由：
├── 世界构建 → 需要强理解能力的模型
├── Agent仿真 → 按原型复杂度分级路由到不同模型
├── 报告生成 → 需要强总结和写作能力的模型
└── 交互追问 → 需要强推理能力的模型
```

各参与方的接入场景：

- **IP方**：提交SKU清单和IP资料 → 拿到预测报告 → 据此决定是否合作和备货量
- **场地方**：提交场地数据 → 拿到"该场地最适合什么IP"的推荐 + 预测GMV
- **运营方**：拿到完整预测报告 + 14天运营节奏建议 → 执行期间每日回传数据获得动态调整建议
- **平台内部**：批量跑多个"场地×IP"组合的仿真 → 找出最高预期GMV的组合 → 推荐给撮合引擎

## 需要在BMAD中明确的设计决策

1. **每天仿真多少Agent？** 50个够不够产生稳定的统计模式？100个？需要用真实数据做敏感性测试
2. **Agent之间要不要互动？** 当前设计每个Agent独立决策。如果加入"看到前面有人排队/有人买了发朋友圈"的社交影响，仿真更真实但复杂度和成本翻倍
3. **仿真粒度？** 按天推进还是按时段（上午/下午/晚上）？影响对"午间白领"和"晚间学生"不同消费模式的捕捉精度
4. **世界状态如何在天与天之间传递？** 当前方案是每天生成新的世界状态摘要，Agent无跨天记忆。是否需要支持"回头客"——前几天来过的Agent第N天又来了？
5. **如何处理"盲盒隐藏款"这类随机因素？** 有人抽到隐藏款发帖引爆传播，这种低概率高影响事件在仿真中怎么触发？
