# 阶段5：报告输出

## 目标

生成三种形式的AI应用价值评估结果，按"先结论后深度"的顺序交付。让用户在30秒内看到核心结论，再根据需求选择深度报告形式。

## 交付顺序与逻辑

### Step 1：结论摘要卡（in-chat 即时呈现）

无需询问，直接生成并发送。内容精炼，聚焦核心结论。

**摘要卡结构**：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 AI价值评估 · 结论摘要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

评估场景：[场景名称]
综合评分：[X.X / 5.0]
评级：[强烈推荐上马 / 建议有条件推进 / 建议先做准备再推进 / 暂不建议]

核心价值：
• 预计年节省成本：约[XX-XX]万元
• 效率提升：[XX]%
• 回收周期：约[X]个月

主要优势：
• [1-2句话，来源于实际数据]

主要风险：
• [1-2句话，来源于实际数据]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

数字必须有来源（"根据您提到的6人团队日处理500工单"），不能用模糊表达（"显著节省"）。

---

### Step 2：询问报告形式偏好

发送摘要卡后，紧接着提问：

> "您想要哪种格式的完整报告？
>
> **A）结构化评分报告**（约3,000-5,000字）
> 适合内部快速决策，包含12个维度评分、价值测算、风险清单和建议行动项。
>
> **B）完整咨询报告**（约8,000-12,000字）
> 适合向管理层或董事会汇报，包含执行摘要、市场对比、实施路线图和ROI详细测算。
>
> **C）两份都要**
>
> 您更倾向于哪种？"

### Step 3：生成选定格式的报告

根据用户选择，生成对应格式。参考 [references/report-templates.md] 中的模板结构。

## 报告生成指导原则

### 数据引用

- **所有数字必须有来源**：用"根据您提到的……"引用用户数据，不得省略来源
- **缺乏实际数据时**：使用行业基准，并明确标注"（基于行业基准估算）"
- **绝对不编造数据**：不确定的内容用区间值或注释，不用没有来源的精确数字

示例：

> ✅ 根据您提到的6人团队、日处理500工单，按人力成本15万/人年估算，年可节省约120-180万元。
>
> ❌ AI将为贵公司带来显著的成本节省。

### 语言风格

- **使用用户自己的表达**：重要判断用引号引用用户原话，增加真实感和认同感
- **具体数字优于模糊描述**：写"约120-180万/年"，不写"显著节省"；写"预计6-9个月回收"，不写"较快回收"
- **专业但不学术**：避免过度堆砌术语；如需使用专业词汇，附上简短解释
- **不用空洞标签**：避免"赋能""数智化转型""生态闭环"等无实质内容的词汇

### AI趋势视角模块（独立呈现）

每份完整报告中包含一个独立模块，对比"传统评估"与"AI趋势修正"的差异：

```
【AI趋势视角修正】

维度       传统评估  趋势修正后  修正原因
效率提升   3.5分    4.2分      LLM处理非结构化文本能力大幅提升，
                               该场景现可自动化比例从30%提升至70%
数据成熟度 2.0分    2.8分      向量数据库降低了非结构化数据的
                               可用门槛，历史数据价值重新评估
```

修正必须说明具体原因，不得只改分数不解释。

## 交付后互动

### 邀请用户校对

报告发送后，主动请用户核对：

> "报告已经生成！请看一下，有没有哪个评分或判断感觉不准确？或者有什么信息补充？"

### 处理修改请求

根据用户反馈，按以下方式处理：

| 反馈类型 | 处理方式 |
|---------|---------|
| 某项评分感觉偏高/偏低 | 追问依据，重新评分，重新计算综合分及受影响层级的得分 |
| 有新的信息要补充 | 将新信息纳入对应维度，更新受影响的评分和结论 |
| 对某项判断有不同看法 | 在报告中标注用户观点（"[用户备注：…]"），保留原评估结论，供读者参考两种视角 |

修改后，受影响的所有数字（层级得分、综合分、价值测算结果）必须一并更新，不得出现数字前后矛盾的情况。

### 收尾

确认用户没有进一步修改需求后：

> "如果没有问题的话，这份评估报告就是最终版了。如果后续有新的场景想评估，随时再来聊！"

## 质量检查（内部自检）

在交付任何内容前，执行以下检查清单。不需要把检查过程呈现给用户。

**结论摘要卡**

- [ ] 所有数字均有来源说明（用户数据或行业基准）
- [ ] 评级与综合分对应关系正确（≥4.0 / 3.0-3.9 / 2.0-2.9 / <2.0）
- [ ] 核心价值数字为区间值（如"120-180万/年"），非精确单点值

**结构化评分报告**

- [ ] 12个维度均有评分（1-5分）
- [ ] 每个评分均有对应的证据或估算依据
- [ ] 层级得分（价值层/就绪度层/风险层）计算正确
- [ ] 综合得分与各层级得分逻辑一致

**完整咨询报告**

- [ ] 执行摘要部分可独立阅读（不依赖后续章节）
- [ ] 至少引用了3处用户原话（用引号标注）
- [ ] ROI测算过程透明，假设条件已列明
- [ ] 实施路线图有时间节点，不是泛泛描述

**AI趋势视角模块**

- [ ] 每项修正均有具体原因说明
- [ ] 修正方向合理（并非所有维度都上调）

**数据完整性**

- [ ] 无编造数据；所有不确定项已用注释或区间值标注
- [ ] 行业基准来源已注明（或标注"基于行业基准"）
