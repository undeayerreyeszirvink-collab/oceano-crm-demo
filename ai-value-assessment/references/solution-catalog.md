## 1. 智能客服与交互

### 1.1 LLM 客服 Agent

| 属性 | 描述 |
|------|------|
| **一句话描述** | 基于大语言模型的端到端对话客服，能理解意图、调用工具、完成多轮任务 |
| **实施复杂度** | 中 |
| **典型周期** | 2–4 个月 |
| **典型成本量级（首年）** | 30万–120万元（含模型调用、平台搭建、集成及人工坐席降本测算） |

**典型适用场景**
- 电商/零售：7×24 小时订单查询、退换货处理、售后跟进
- 金融：信用卡账单查询、产品咨询、贷款预审引导
- 政务/公共服务：政策问答、业务办理引导、投诉受理

**技术方案概述**

以 LLM（如 GPT-4/Claude/文心）为核心推理引擎，结合对话管理框架（如 LangChain、Rasa）构建多轮对话 Agent。通过 Function Calling / Tool Use 机制集成后端 API（订单系统、CRM、知识库），实现意图识别 → 槽位填充 → 工具调用 → 结果回复的完整链路。配备人工转接兜底策略及对话质检模块。

**关键前置条件**
- 已有标准化的后端 API 或可快速封装的数据接口
- 具备历史客服对话数据用于意图分析与测试（建议 ≥ 5,000 条）
- 明确的升级/转人工规则及服务 SLA 定义

| 属性 | 描述 |
|------|------|
| **一句话描述** | 自动识别工单类型、紧急程度并路由至最优处理团队或个人 |
| **实施复杂度** | 低 |
| **典型周期** | 1–2 个月 |
| **典型成本量级（首年）** | 10万–30万元（含模型微调、系统集成及测试） |

**典型适用场景**
- IT 服务台：硬件故障、软件问题、权限申请自动分流
- 制造业：设备报修工单按型号/区域/优先级自动派工

**技术方案概述**

使用文本分类模型（微调 BERT/RoBERTa 或 Few-shot LLM）对工单主题进行多标签分类，结合规则引擎（优先级规则、工作负载均衡）实现智能路由。模型持续从人工修正中学习，支持新类别扩展。与 ServiceNow、Jira、Zendesk 等主流工单系统集成。

**关键前置条件**
- 现有工单系统可提供 API 或 Webhook 集成能力
- 历史工单数据需包含分类标签（建议每类 ≥ 200 条）

| **实施复杂度** | 中 |
| **典型周期** | 2–3 个月 |
| **典型成本量级（首年）** | 20万–60万元（含实时流处理、知识库建设及坐席终端集成） |

**典型适用场景**

**技术方案概述**

- 满足数据合规要求（如客户对话录音的留存与使用授权）

## 2. 文档与知识处理

### 2.1 文档智能提取（OCR + LLM）

| 属性 | 描述 |
|------|------|
| **一句话描述** | 从扫描件、PDF、图片中自动提取结构化信息，替代人工录入 |
| **实施复杂度** | 中 |
| **典型周期** | 2–4 个月 |
| **典型成本量级（首年）** | 20万–80万元（含 OCR 平台、LLM 后处理、对接 ERP/业务系统） |

**典型适用场景**
- 物流/贸易：提单、报关单、发票自动解析录入
- 医疗：病历、检验报告结构化入库
- 政府/法务：审批文件、证照信息自动提取归档

**技术方案概述**

采用高精度 OCR 引擎（如 PaddleOCR、Azure Form Recognizer、Textract）识别文字版面，再由 LLM（Prompt 工程或微调）完成关键字段抽取、格式化输出（JSON/XML）。针对复杂版式（表格、多栏、手写体）需专项训练或人工复核队列。结果自动写入目标系统（ERP、档案库）。

**关键前置条件**
- 文档类型相对固定（版式变化不超过 5–10 种）
- 可提供标注样本（每种版式建议 ≥ 100 份）
- 目标系统具备批量写入 API

### 2.2 企业知识库问答（RAG）

| 属性 | 描述 |
|------|------|
| **一句话描述** | 基于检索增强生成（RAG），让员工用自然语言查询企业内部知识 |
| **实施复杂度** | 中 |
| **典型周期** | 2–3 个月 |
| **典型成本量级（首年）** | 15万–50万元（含知识库建设、向量数据库、LLM 调用及门户开发） |

**典型适用场景**
- 大型企业：员工查询 HR 政策、IT 操作手册、内部流程规定
- 制造业：工程师查询设备维护手册、质量标准、BOM 信息
- 金融：合规人员查询监管规定、产品条款、历史案例

**技术方案概述**

文档经分块（Chunking）和 Embedding 处理后存入向量数据库（如 Milvus、Weaviate、Pinecone）。用户提问时，通过语义检索召回相关段落，结合 LLM 生成准确、有引用来源的回答（RAG 架构）。支持权限管控（不同角色查询不同文档集），配备反馈机制持续优化检索质量。

**关键前置条件**
- 知识文档已数字化（PDF/Word/Confluence/Wiki 等）
- 文档更新频率可管理，有责任人维护知识库
- 明确的访问权限层级设计

### 2.3 合同 / 法规审查

| 属性 | 描述 |
|------|------|
| **一句话描述** | 自动扫描合同或法规文本，标记风险条款、偏差点及合规缺口 |
| **实施复杂度** | 高 |
| **典型周期** | 3–6 个月 |
| **典型成本量级（首年）** | 50万–200万元（含法律知识图谱建设、模型定制、法务团队协作流程改造） |

**典型适用场景**
- 企业法务部：批量审查供应商合同，识别不平等条款
- 金融机构：贷款协议、衍生品合同的合规性自动校验
- 跨国企业：多国法规符合性扫描（如 GDPR、个人信息保护法）

**技术方案概述**

构建领域法律知识库（标准条款、风险词典、法规条文），使用 LLM（含 Long Context 能力）逐条对比合同文本与标准模板，输出风险评分和问题清单。核心技术包括：条款结构化解析、语义相似度比对、规则引擎兜底。系统辅助法务人员决策，不替代最终判断。

**关键前置条件**
- 法务团队参与定义风险规则和审查标准
- 历史合同样本用于测试（建议 ≥ 200 份，含标注）
- 明确系统定位为"辅助工具"而非"替代法律意见"

## 3. 数据分析与洞察

### 3.1 自然语言数据查询（Text-to-SQL）

| 属性 | 描述 |
|------|------|
| **一句话描述** | 业务人员用自然语言提问，系统自动生成 SQL 并返回数据结果 |
| **实施复杂度** | 中 |
| **典型周期** | 1–3 个月 |
| **典型成本量级（首年）** | 15万–45万元（含 Schema 映射、语义层建设、前端界面） |

**典型适用场景**
- 零售/电商：运营人员查询"上周华东区 TOP10 SKU 的复购率"
- 制造业：管理层查询"本季度各产线的良品率对比"
- 金融：风控人员查询"近 30 天逾期率超过 5% 的客户群体特征"

**技术方案概述**

构建数据库 Schema 的语义描述层（表/字段含义、业务术语映射），LLM 结合 Schema 上下文将自然语言转换为 SQL（支持多表 JOIN、聚合、子查询）。执行前进行 SQL 安全校验（防止数据破坏性操作），结果以图表或表格呈现，支持追问和钻取。

**关键前置条件**
- 数据仓库/BI 层已就绪，有清晰的 Schema 文档
- 核心业务指标有规范的业务定义（避免歧义）
- 数据权限管控机制已部署（避免越权查询）

---

### 3.2 预测分析（需求 / 销售预测）

| 属性 | 描述 |
|------|------|
| **一句话描述** | 结合历史销售数据与外部特征，预测未来一段时间的需求或销售量 |
| **实施复杂度** | 中 |
| **典型周期** | 2–4 个月 |
| **典型成本量级（首年）** | 20万–70万元（含特征工程、模型训练、MLOps 管道及业务系统集成） |

**典型适用场景**
- 快消品/零售：SKU 级别的周/月销售预测，驱动补货计划
- 制造业：原材料需求预测，优化采购与库存水位
- 电商：大促活动期间流量与订单量预测，支持弹性扩容

**技术方案概述**

采用时序预测模型（如 Prophet、LightGBM、Transformer-based 时序模型），融合历史销售、促销日历、节假日、天气、价格弹性等特征。模型按 SKU/地区/渠道分层训练，输出预测值及置信区间。结果推送至 ERP/SCM 系统，支持人工调整和反馈闭环。

**关键前置条件**
- 历史销售数据 ≥ 2 年（含促销活动标记）
- 数据质量可靠（缺失率 < 15%，无大量异常值）
- 业务侧认可"预测误差"合理范围（如 MAPE ≤ 15%）

### 3.3 异常检测与告警

| 属性 | 描述 |
|------|------|
| **一句话描述** | 实时监测业务指标或系统日志，自动发现异常并触发告警 |
| **实施复杂度** | 中 |
| **典型周期** | 2–3 个月 |
| **典型成本量级（首年）** | 20万–60万元（含流式数据接入、模型部署、告警平台集成） |

**典型适用场景**
- 金融风控：交易欺诈实时检测（卡片盗刷、账户异常登录）
- 电商运营：支付成功率、转化漏斗出现骤降时秒级告警
- 工业 IoT：设备传感器指标异常预警，预防性维护

**技术方案概述**

基于流式数据平台（Kafka/Flink）实时摄取指标数据，使用统计方法（Z-Score、IQR）结合机器学习模型（Isolation Forest、LSTM Autoencoder）进行异常评分。异常事件分级（告警/警告/提示）并通过企业消息（钉钉/飞书/Slack）或 PagerDuty 推送。支持自定义阈值和规则，减少误报。

**关键前置条件**
- 数据采集管道已就绪（实时或近实时，延迟 ≤ 30 秒）
- 历史异常数据有标注或可通过专家知识定义异常模式
- 告警接收方已明确，有 On-call 机制

## 4. 流程自动化

### 4.1 审批智能路由

| 属性 | 描述 |
|------|------|
| **一句话描述** | 根据申请内容自动判断审批层级和路由路径，减少人工判断和转发 |
| **实施复杂度** | 低 |
| **典型周期** | 1–2 个月 |
| **典型成本量级（首年）** | 8万–25万元（含流程梳理、规则引擎配置、OA/ERP 集成） |

**典型适用场景**
- 采购审批：根据采购金额、供应商类型、预算科目自动决定审批链
- 费用报销：差旅、招待、培训等不同类型按规则路由至对应负责人
- IT 权限申请：根据申请系统级别和岗位匹配自动批准或上报

**技术方案概述**

结合 NLP 分类（识别申请类型）和规则引擎（金额阈值、组织架构、业务规则），动态生成审批流。LLM 用于处理非结构化申请内容（如自由格式的说明文字），提取关键要素后映射至标准流程。与钉钉、企业微信、OA 系统（SAP、用友、泛微）集成。

**关键前置条件**
- 审批规则已文档化且相对稳定（变更频率 ≤ 季度级）
- OA/ERP 系统支持 API 集成或流程定制
- 业务部门愿意参与规则梳理（通常 2–4 轮工作坊）

|------|------|
| **一句话描述** | RPA 处理结构化操作，AI 处理非结构化判断，二者协同完成端到端流程 |

| **典型周期** | 3–6 个月 |

**典型适用场景**
- 财务对账：自动下载银行流水，AI 匹配凭证，RPA 录入 ERP
- 人事入职：AI 解析简历和证件信息，RPA 自动完成系统账号创建和权限配置
- 供应链：AI 解析供应商邮件中的报价单，RPA 自动更新询价系统

**技术方案概述**

以 RPA 平台（UiPath、Automation Anywhere、影刀）为执行引擎，AI 模块（OCR、NLP、LLM）作为"智能眼睛和大脑"嵌入 Bot 流程中。关键设计：AI 置信度低时触发人工复核队列（Human-in-the-loop），异常处理和重试机制完善，监控看板追踪自动化率与错误率。

**关键前置条件**
- 目标流程已充分梳理（流程图、异常分支、边界条件）
- IT 部门支持 RPA Bot 运行环境（服务器、网络权限）
- 流程稳定性较高（UI 变更频率低，接口不频繁改版）

| **典型周期** | 1–2 个月 |

**技术方案概述**

**关键前置条件**

- 主要邮件类型和处理规则可被枚举（建议 ≤ 20 种主要场景）
- 数据安全合规审查（邮件内容处理的隐私要求）

## 5. 内容生成

### 5.1 营销内容批量生成

| 属性 | 描述 |
|------|------|
| **一句话描述** | 基于产品信息和受众特征，批量生成多渠道营销文案、图片描述和广告素材 |
| **实施复杂度** | 低 |
| **典型周期** | 1–2 个月 |
| **典型成本量级（首年）** | 10万–40万元（含平台搭建、品牌规范训练、内容审核流程） |

**典型适用场景**
- 电商：大促期间批量生成商品详情页、主图文案、短视频脚本
- 快消品：针对不同区域/人群生成本地化广告语和社交媒体帖子
- SaaS/软件：产品功能更新的多版本发布公告（官网、邮件、公众号）

**技术方案概述**

建立品牌声音（Brand Voice）提示词库和内容模板，输入产品属性（SKU 信息、卖点、目标人群），LLM 批量生成多渠道版本（微信公众号、抖音脚本、电商详情页、Push 通知）。配备人工审核节点和内容合规检查（广告法词汇过滤）。支持 A/B 版本对比和效果反馈闭环。

**关键前置条件**
- 品牌调性和内容规范已文档化（语气、禁用词、视觉风格）
- 产品信息来源有结构化数据库（PIM 或 Excel 均可）
- 内容审核责任人已确定，审核 SLA 明确

### 5.2 报告自动化

**典型适用场景**

- 企业管理：月度运营报告（销售、财务、人力）自动汇编发送管理层

**技术方案概述**

报告模板定义数据查询逻辑（连接 BI/数据仓库）和文字框架，调度器（Airflow/定时任务）触发数据拉取，LLM 基于数据生成趋势解读、异常说明和执行摘要（Executive Summary），最终渲染为 PDF/PPT/HTML。支持个性化收件人定制（不同角色看不同版本）。

**关键前置条件**
- 核心指标数据源已打通，数据质量可靠
- 报告结构相对固定（允许季度级调整）
- 报告消费方对 AI 生成文字解读有接受度（需明确标注）

## 6. 质检与监控

### 6.1 视觉质检（工业）

| 属性 | 描述 |
|------|------|
| **一句话描述** | 通过工业相机 + 深度学习模型实时检测产品外观缺陷，替代人工目检 |
| **实施复杂度** | 高 |
| **典型周期** | 3–6 个月 |
| **典型成本量级（首年）** | 80万–200万元（含硬件采购、模型训练、产线集成及调试） |

**典型适用场景**
- 3C/半导体：PCB 焊点检测、芯片表面划伤识别
- 汽车零部件：铸件气孔、表面划痕、尺寸偏差检测
- 食品/药品：包装破损、异物混入、标签错误检测

**技术方案概述**

工业相机（线扫/面扫）采集图像，经图像预处理后送入深度学习模型（YOLOv8、EfficientDet 或定制 CNN）进行缺陷分类和定位（Bounding Box）。模型训练需 500–2,000 张标注缺陷图像，支持增量学习（新缺陷类型快速扩展）。检测结果实时反馈至产线 PLC，触发剔除机构，并汇入 MES 质量报表。

**关键前置条件**
- 检测位置可稳定安装工业相机（光源、震动、遮挡等环境可控）
- 各类缺陷样本可采集标注（初期至少 200 张/类型，含正常品）
- 产线支持与视觉系统的信号集成（I/O、OPC-UA、Modbus 等）

## 7. 销售与 CRM

### 7.1 销售线索智能评分

| 属性 | 描述 |
|------|------|
| **一句话描述** | 对进入漏斗的线索自动评分和优先级排序，帮助销售聚焦高转化潜力客户 |
| **实施复杂度** | 中 |
| **典型周期** | 2–3 个月 |
| **典型成本量级（首年）** | 15万–45万元（含 CRM 集成、特征工程、模型训练及销售工作台改造） |

**典型适用场景**
- B2B SaaS：试用用户行为数据驱动的付费转化概率预测
- 企业保险：保险经纪人线索库智能排序，优先跟进高意向客户
- 制造业/工程销售：根据企业特征（规模、行业、采购信号）评估成单概率

**技术方案概述**

融合线索来源（官网表单、内容下载、活动签到）、行为数据（邮件打开、页面浏览时长）和企业画像（爬取官网、工商信息、财务报告）特征，训练 XGBoost/LightGBM 评分模型。评分实时写入 CRM（Salesforce、HubSpot、纷享销客），在销售工作台突出高分线索。支持模型定期重训（建议月频）。

**关键前置条件**
- CRM 中有历史线索转化结果标签（建议 ≥ 1,000 条有结果的线索）
- 销售团队愿意配合数据录入（行为数据质量依赖录入规范）
- CRM 系统支持自定义字段和 API 写入

| 属性 | 描述 |
|------|------|
| **一句话描述** | 预测订阅/续费客户的流失风险，提前触发挽留行动 |
| **实施复杂度** | 中 |
| **典型周期** | 2–4 个月 |
| **典型成本量级（首年）** | 20万–60万元（含数据管道建设、模型训练、客户成功工作台集成） |

**典型适用场景**
- SaaS/订阅服务：合同到期前 60–90 天预测续费风险，触发 CSM 干预
- 电信运营商：识别高流失风险用户，个性化保留优惠定向投放
- 零售会员：会员活跃度下降预警，定向发放唤回券

**技术方案概述**

基于客户健康度特征（产品使用频率/深度、支持工单频次、NPS 评分、付款行为）构建生存分析模型（Cox 比例风险模型）或二分类模型（流失/不流失）。输出 30/60/90 天流失概率，按风险等级推送至客户成功（CS）团队，配套建议干预动作（电话外呼、专属折扣、功能培训邀请）。

**关键前置条件**
- 历史客户流失数据 ≥ 12 个月，且流失原因有一定标注
- 产品使用数据可被采集（埋点完善，或 SaaS 有内置分析能力）
- 客户成功团队有标准化的挽留 Playbook

### 7.3 个性化推荐引擎

| 属性 | 描述 |
|------|------|
| **一句话描述** | 基于用户行为和偏好，实时推荐最相关的产品、内容或服务，提升转化和复购 |
| **实施复杂度** | 高 |
| **典型周期** | 3–5 个月 |
| **典型成本量级（首年）** | 60万–180万元（含算法研发、实时推理基础设施、A/B 测试框架及持续迭代） |

**典型适用场景**
- 电商平台："猜你喜欢"、购物车关联推荐、邮件个性化选品
- 内容/媒体平台：视频、文章、课程的个性化 Feed 流
- 金融理财：基于风险偏好和持仓情况的产品推荐

**技术方案概述**

构建多路召回（协同过滤、基于内容、热门兜底）+ 精排（LTR 模型：LambdaRank/DIN/DIEN）的两阶段推荐架构。用户行为实时更新（Kafka 流处理），特征存入特征存储（Redis + 特征平台），推理服务部署于 GPU 集群实现毫秒级响应。通过严格的 A/B 测试框架验证推荐效果（CTR、CVR、GMV 提升）。

**关键前置条件**
- 用户行为数据已采集（点击、购买、停留、收藏），且日活跃用户 ≥ 1 万（冷启动问题需评估）
- 商品/内容有完整的结构化标签（类目、属性、标签体系）
- 具备实时计算基础设施或愿意投入相应基础设施建设
