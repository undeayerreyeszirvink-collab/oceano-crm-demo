## 1. 能力边界变化

### LLM 能力现状

#### 文本理解和生成
- **当前水平**：GPT-4o、Claude 3.5 Sonnet、Gemini 2.0 Flash 等主流模型在通用文本任务上已接近人类水平
- **适用场景**：文档摘要、内容撰写、客服对话、知识问答、语言翻译、报告生成
- **局限性**：长文档（>100K tokens）的跨段落一致性仍有挑战；专业领域（法律判决、医疗诊断）需人工审核；幻觉问题在低频知识场景仍存在

#### 多模态理解
- **当前水平**：图像识别与描述已高度成熟；视频理解（逐帧分析）实用化；音频转录（Whisper 级别）接近人类水平
- **适用场景**：图文混排内容提取、产品图片分析、发票/表单 OCR、视频内容索引、会议音频转录
- **局限性**：实时视频流处理延迟较高；复杂图表（CAD、电路图）理解准确率约 70-80%；音频情感识别仍不稳定

#### 代码生成
- **当前水平**：主流模型在常见语言（Python、TypeScript、Go、Java）上可完成函数级到模块级代码生成，准确率约 80-90%（HumanEval 基准）
- **适用场景**：CRUD 代码自动生成、单元测试生成、代码重构与注释、SQL 查询生成、API 接口对接
- **局限性**：超过 5000 行的大型项目级生成仍需人工拆解；领域特定框架（低代码平台自定义逻辑）准确率下降至 50-60%

#### 推理能力
- **当前水平**：o1/o3、Claude 3.7（扩展思考）等推理增强模型在数学竞赛（MATH 基准）达 90%+，逻辑推理（ARC-AGI）有显著提升
- **适用场景**：多步骤数学计算、复杂逻辑判断、结构化规划与分解、因果分析
- **局限性**：开放世界规划（需要物理常识）可靠性约 60-70%；推理时间成本高（o3 推理约为标准模型 5-10 倍）；长链推理（>20 步）累计误差明显

### Agent 能力现状

#### 多步骤任务执行
- **当前水平**：工具调用（Function Calling）已成熟，主流框架（LangGraph、AutoGen、CrewAI）支持复杂工作流编排；计算机使用（Computer Use）实用化但不稳定
- **典型能力**：网页搜索 + 信息提取 + 报告生成（3-5 步）成功率约 85%；代码执行 + 调试循环成功率约 75%；跨系统数据读写（CRM + ERP）成功率约 70%
- **局限性**：长流程（>10 步）可靠性显著下降；异常处理能力弱，需要人工设计回退逻辑

#### 自主决策
- **可靠性水平**：结构化、规则明确场景（数据分类、格式转换）可靠性约 90%；半结构化场景（客户意图识别）约 75%；开放决策场景（商业策略建议）约 50%，需人工监督
- **实用建议**：在高风险决策节点（财务审批、客户数据变更）保留人工确认步骤；自主决策适合低风险、高频、规则清晰的任务

#### 协作能力
- **多 Agent 模式**：监督者-执行者（Supervisor-Worker）、流水线（Pipeline）、辩论（Debate）三种主流模式均已有生产案例
- **当前可靠性**：两 Agent 协作成功率约 80%；三个以上 Agent 协作复杂度指数上升，成功率约 60-70%
- **主流框架成熟度**：LangGraph（稳定）、AutoGen v0.4（稳定）、CrewAI（生产可用）、Dify（低代码，适合非技术团队）

### 修正规则（能力维度）

| 场景特征 | 修正维度 | 修正幅度 | 原因 |
|---------|---------|---------|------|
| 非结构化文本处理（摘要、提取、分类） | 技术复杂度↓ | -0.5 ~ -1.0 | LLM 原生擅长，无需定制开发 |
| 多步骤流程自动化（Agent 工作流） | 可行性↑ | +0.5 | Agent 框架成熟，实施路径清晰 |
| 图像/文档多模态理解 | 技术复杂度↓ | -0.3 ~ -0.5 | 多模态 API 成熟，直接调用即可 |
| 创意内容生成（营销文案、报告初稿） | 商业价值↑ | +0.3 ~ +0.5 | 人工替代效果已验证，ROI 明确 |
| 实时对话交互（客服、销售助手） | 技术复杂度↓ | -0.5 ~ -0.8 | 成熟方案多，部署周期短 |
| 复杂推理与规划（超过 10 步决策链） | 技术风险↑ | +0.5 ~ +1.0 | 可靠性尚未达到生产要求，需人工兜底 |
| 跨系统数据集成（需对接 3+ 外部 API） | 实施复杂度↑ | +0.5 ~ +0.8 | 集成工程量大，与 AI 技术本身无关 |
| 领域极度专业化（医疗诊断、法律判决） | 合规风险↑ | +1.0 | 需专业审核，监管要求高 |

## 2. 成本结构变化

### 推理成本趋势（截至 2026 Q1）

#### 主流模型 API 成本

| 模型 | 输入成本（/M tokens） | 输出成本（/M tokens） | 与 1 年前对比 |
|------|---------------------|---------------------|-------------|
| GPT-4o (OpenAI) | $2.50 | $10.00 | ↓ 约 40%（2025Q1 为 $5/$15） |
| Claude 3.5 Sonnet (Anthropic) | $3.00 | $15.00 | ↓ 约 30% |
| Gemini 2.0 Flash (Google) | $0.10 | $0.40 | ↓ 约 50%（新一代大幅降价） |
| GPT-4o mini | $0.15 | $0.60 | ↓ 约 35% |
| Claude 3.5 Haiku | $0.80 | $4.00 | ↓ 约 25% |
| o3-mini（推理模型） | $1.10 | $4.40 | 新增（推理模型成本已大幅下降） |

> 趋势：主流旗舰模型成本年均下降 30-50%，轻量模型（Flash/mini/Haiku 级别）已进入超低成本区间，适合高频调用场景。

#### 开源模型自部署成本

| 部署方式 | 月成本估算 | 适用场景 |
|---------|-----------|---------|
| Llama 3.3 70B（云端 GPU，按需） | $300-800/月（中等流量） | 数据合规要求高、中等并发 |
| Qwen2.5 72B（云端 GPU，按需） | $250-700/月 | 中文场景优化，成本较低 |
| 小型模型 8B（A100 单卡） | $150-400/月 | 高频低复杂度任务，延迟敏感 |
| 私有化部署（自建 GPU 集群） | 初始投入 $50K+，月运营 $5-20K | 数据不出域要求严格的大型企业 |

> 趋势：开源模型与闭源 API 的能力差距缩小至约 10-20%（通用任务），性价比优势明显。

#### 微调成本

| 微调方式 | 成本估算 | 适用场景 |
|---------|---------|---------|
| OpenAI Fine-tuning（GPT-4o mini） | $3-8/1M tokens 训练数据 | 快速领域适配，无需 GPU 资源 |
| LoRA 微调（自托管 70B 模型） | $500-2000（一次性，云端训练） | 领域特定任务，长期使用 |
| 全量微调（7B 模型） | $200-800（A100 4-8 小时） | 特殊场景定制，数据量充足 |

## 3. 实施模式变化

### 当前主流实施模式

#### 模式一：API 直接调用（最快、最轻）
- **适用场景**：单一功能增强（文本摘要、内容生成、智能问答）、原型验证、中小规模应用
- **典型周期**：2-6 周（含集成调试）
- **技术要求**：后端开发能力即可，无需 AI 专业知识
- **成本结构**：主要为 API 调用费，无基础设施成本
- **典型案例**：邮件自动分类、合同关键信息提取、客服 FAQ 自动回复
- **2026 现状**：OpenAI、Anthropic、Google AI SDK 成熟稳定，Prompt 工程最佳实践已标准化

#### 模式二：低代码/Agent 平台搭建（中等）
- **适用场景**：多步骤业务流程自动化、跨系统集成、非技术团队主导的 AI 应用
- **典型周期**：4-12 周（含流程设计和测试）
- **技术要求**：业务分析能力 + 基础配置能力；复杂场景需开发支持
- **成本结构**：平台订阅费（$100-2000/月）+ 少量开发工时
- **主流平台**：Dify（开源可私有化）、Coze（字节）、Langflow、n8n（含 AI 节点）、Microsoft Copilot Studio
- **典型案例**：销售线索自动跟进、财务报表自动生成、HR 入职流程自动化
- **2026 现状**：Dify 1.x 已支持企业级多租户，Agent 可视化编排成熟度大幅提升

#### 模式三：定制开发 + 微调（最重）
- **适用场景**：高度专业化领域（医疗、法律、金融）、数据不出域要求、超大规模并发、深度与现有系统集成
- **典型周期**：3-9 个月（含数据准备、训练、测试、部署）
- **技术要求**：AI 工程师 + MLOps + 领域专家
- **成本结构**：人力成本（50-80%）+ GPU 资源 + 持续运维
- **典型案例**：银行反欺诈模型、医疗影像辅助诊断、工业质检视觉模型
- **2026 现状**：RAG（检索增强生成）已成为知识库场景标配，替代大量微调需求；LoRA 微调成本下降使定制门槛降低

---

### 修正规则（实施模式维度）

| 场景特征 | 推荐模式 | 修正维度 | 修正幅度 | 原因 |
|---------|---------|---------|---------|------|
| 单一功能、明确需求、快速上线 | API 直接调用 | 实施周期↓ | -0.5 ~ -1.0 | 无需架构设计，直接集成 |
| 多步骤流程、跨系统、非技术主导 | 低代码平台 | 技术门槛↓ | -0.5 ~ -0.8 | 平台封装复杂度，业务人员可配置 |
| 数据合规要求高（金融/医疗/政府） | 定制开发 | 实施成本↑ | +1.0 ~ +1.5 | 私有化部署增加显著工程量 |
| 已有类似开源方案或模板 | API/低代码 | 开发成本↓ | -0.5 ~ -1.0 | 可复用已验证架构，减少试错 |
| 需要实时流式响应（<500ms） | API 直接调用 | 技术约束↑ | +0.3 | 低代码平台延迟较高，需评估 |
| 团队无 AI 开发经验 | 低代码平台 | 实施风险↓ | -0.3 ~ -0.5 | 平台降低技术门槛，缩短学习曲线 |
| 需要高度定制化模型能力 | 定制开发+微调 | 技术复杂度↑ | +0.8 ~ +1.2 | RAG 无法满足时才考虑微调 |
| 原型验证/POC 阶段 | API 直接调用 | 投入成本↓ | -1.0 | 极低成本快速验证可行性 |
