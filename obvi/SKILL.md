# IT服务合同审查 AI 技能

## 概述

本技能基于52条合同审核规则集，对IT服务类合同进行系统化审查。审查覆盖17个一级分类、合同全生命周期的关键条款，并按照6种业务类型进行差异化审核。

## 审查流程

### Step 1: 确定合同业务类型

首先识别合同属于以下哪种业务类型，因为不同业务类型对条款的必要性要求不同：

| 编号 | 业务类型 | 典型特征 |
|------|---------|---------|
| 1 | 资源服务（框架） | 人员外包、驻场服务、框架协议、按人天/人月计费 |
| 2 | 实施开发（项目） | 项目制交付、里程碑验收、定制开发 |
| 3 | 软件销售/转售 | 软件许可、License转售、SaaS订阅 |
| 4 | 硬件转售 | 服务器、网络设备等硬件采购转售 |
| 5 | 运维服务 | 系统运维、IT运维外包、技术支持 |
| 6 | 咨询服务 | 管理咨询、技术咨询、方案规划 |

如果无法确定业务类型，询问用户。如果合同涵盖多种业务类型，按最高必要性标准审核。

### Step 2: 逐条审查

读取 `references/rules-complete.md` 获取完整的52条规则，逐条对合同进行审查。

对每条规则的审查逻辑：

1. **判断必要性**：根据合同业务类型查看该条款是"必要""非必要"还是"不适用"
   - **必要**：合同必须包含该条款，缺失则为高风险（条款缺失）
   - **非必要**：合同可以不包含，但如果包含且违反审核指引则按指引判定风险
   - **不适用**：该类型合同不应出现此条款，如出现则为高风险
2. **定位条款**：在合同中查找对应条款内容
3. **执行审核指引**：按照规则中的审核指引逐项检查
4. **判定风险等级**：
   - **条款缺失**：必要条款完全不存在 → 高风险
   - **内容缺失**：条款存在但关键内容未填写完整 → 需补充
   - **高风险**：严重违反审核指引，可能导致重大法律风险
   - **中风险**：违反审核指引，需要修改条款
   - **低风险**：非常规条款，需要关注但不强制修改

### Step 3: 生成审查报告

输出格式如下：

```
# 合同审查报告

## 基本信息
- 合同名称：[合同标题]
- 合同类型：[业务类型]
- 审查日期：[日期]
- 审查规则版本：IT服务合同审查规则集 v1.0（52条）

## 风险总览
- 高风险：X 条
- 中风险：Y 条
- 低风险：Z 条
- 条款缺失：A 条
- 内容缺失：B 条

## 详细审查结果

### [风险等级] 规则编号 - 条款名称
- **所属分类**：一级分类 > 二级分类 > 三级分类
- **必要性**：必要/非必要/不适用
- **合同原文**：[引用合同中的对应内容]
- **问题描述**：[具体问题]
- **风险等级**：条款缺失/内容缺失/高风险/中风险/低风险
- **修改建议**：[具体修改建议]
- **参考范本**：[标准条款参考]

...（按风险等级从高到低排列）

## 无风险条款（合规）
[列出审查通过的条款]

## 审查结论与建议
[总结性意见]
```

## 风险判定规则

### 条款缺失（高风险）
当必要条款在合同中完全不存在时触发。例如：
- 资源服务合同缺少"结算机制"条款
- 所有类型合同缺少"支付条件"条款
- 所有类型合同缺少"争议解决"条款

### 内容缺失
条款框架存在但关键信息未填写。例如：
- "签署时间：____年__月__日" 但未填写具体时间
- 有"法定代表人"字段但为空

### 高风险
- 竞业限制条款的存在
- 合同变更未经双方协商一致即可变更
- 一方提出变更另一方必须接受或未回复视为接受
- 保密违约金按双方合作期间业务往来总金额计算

### 中风险
- 违约责任不对等（甲乙方违约金比例/上限不一致）
- 支付方式非银行转账/电汇/承兑汇票
- 价款大小写不一致
- 附件冲突时由甲方选择适用
- 仲裁和诉讼同时约定

### 低风险
- 签约时间早于合同审核时间
- 有效期超过三年
- 保密期限超过五年或永久
- 约定适用非中国法律

## 关键审查要点速查

读取 `references/rules-complete.md` 获取所有52条规则的完整审核指引。

以下为最重要的必要条款（所有或多数业务类型必须具备）：

| 规则 | 条款 | 必要的业务类型 |
|------|------|--------------|
| R1-R2 | 甲乙方主体信息 | 全部6种 |
| R5 | 签署方式与生效条件 | 全部6种 |
| R8 | 合同价款 | 除资源服务外的5种 |
| R9 | 额外费用 | 资源服务(框架) |
| R11 | 结算机制 | 资源服务(框架) |
| R14 | 支付条件方式期限 | 全部6种 |
| R22 | 甲方迟延付款违约责任 | 全部6种 |
| R38 | 争议解决方式 | 全部6种 |
| R43 | 合同份数 | 全部6种 |
| R48-R49 | 服务地点和方式 | 资源服务、实施开发、运维、咨询 |

## 特殊审查逻辑

### 违约责任对等性审查
甲方"迟延付款"违约责任（R22）需要与乙方"迟延交付/项目中止/终止/迟延验收"违约责任（R25）进行对比，检查：
- 每日违约金比例是否对等
- 违约金上限是否对等
- 赔偿范围是否对等

### 分类关系规则
- 甲方违约责任：优先识别"迟延付款""项目中止/终止/迟延验收"，无法归入的放入"其他"
- 乙方违约责任：优先识别"迟延交付/项目中止/终止/迟延验收""不符合验收标准""未按约定投入资源"，无法归入的放入"其他"
- 权利义务：放到所有分类最后做拆分和兜底识别

### 业务类型特殊规则
- **资源服务（框架）**：必须有结算机制、额外费用（含加班费）条款，不适用"结算争议处理""迟延交付违约""不符合验收标准"
- **软件销售/转售**：必须有已有知识产权归属条款，不适用结算相关条款
- **硬件转售**：必须有已有知识产权归属条款，不适用结算、资源投入相关条款

## 注意事项

- 合同中"甲方"指客户方（买方/委托方），"乙方"指服务供应商（卖方/供方/受托方）
- 审查立场为乙方（服务供应商）视角，关注保护乙方利益
- 审核指引中的数值阈值（如违约金比例、金额上限等）是硬性标准，严格执行
- 对于审核指引为"无"的规则，仅做条款识别和分类，不做风险判定
- 参考范本仅供参考，不作为风险判定依据
